# عقود المرحلة الأولى

تاريخ الفحص: 2026-10-04. المرجع الأول مساعدة agy المحلية، وتطابق Windows وTermux مقرر من المستخدم. هذه وثيقة عقد وقبول، وليست شهادة نجاح الهاتف.

## أوامر CLI المثبتة بالمساعدة

| الوظيفة | العقد | حدود الإثبات |
|---|---|---|
| جلسة تدفق | --input-format stream-json مع --output-format stream-json | وجود flags مثبت؛ الدور الفعلي غير مجرب هنا |
| الاستئناف | --conversation ID؛ --continue للأحدث | الاستئناف الحي يحتاج اختباراً |
| الخيارات | --model و--agent و--effort و--mode و--sandbox و--project | صلاحية النموذج/effort تحتاج جواب CLI الفعلي؛ لا تغيير ضمني |
| عرض النماذج | agy models | الأمر موجود؛ التنفيذ المحلي طلب دخولاً ولم يعط قائمة |
| عرض الوكلاء | agy agent أو agy agents | الأمر موجود؛ لم يحصل فحص سابق على قائمة يعتمد عليها |
| مهلة الدور | --print-timeout؛ صفر ينتظر الدور | لا يغني عن بروتوكول الإلغاء وملك العملية |
| MCP | agy mcp add/remove/list/enable/disable | هذه أوامر إدارة إعداد، وليست إثبات سلامة الاتصال |
| Plugins | agy plugin وأسماؤه الفرعية | خارج تغيير المرحلة الأولى |
| التحكم البعيد | agy remote-control | لا يُفعل؛ اتصال التطبيق يبقى loopback |

عقد MCP add: `agy mcp add [flags] <name> <commandOrUrl> [args...]`. الأنواع stdio وhttp، وخيارات env/header متكررة. Flags تسبق اسم الخادم؛ http/https يُكشفان آلياً؛ الفاصل -- عند الحاجة حسب المساعدة. لا تُطبع أسرار env/header أو سطر الأمر الكامل. لا تشغيل لأي add/remove/enable/disable في فحص المرحلة الأولى.

## حالات العقد المستهدف

الدور: running/completed/failed/cancelled/interrupted. اكتمال التدفق لا يثبت إنجاز الأداة. معرف بدء الطلب client_request_id يمنع الدور المكرر؛ اختلاف الطلب بالمعرف نفسه تعارض. حدث SSE محفوظ ومعرفه متزايد؛ سقوط السجل replay_unavailable، وليس إذناً بإعادة العمل.

الإعدادات برقم مراجعة وكاتب واحد. API له code/message/request_id في الخطأ. الاقتران قصير العمر، وجلسة المتصفح HttpOnly وSameSite=Strict؛ أفعال التغيير محمية من CSRF. اتصال Android مستقل المصادقة. كل هذه عقود لاحقة، ولم تُنفذ هنا.

## قبول الهاتف: أدلة مطلوبة قبل المرحلة الثانية

- تأمين نسخة بيانات الهاتف والإعدادات والمحادثات، وتوثيق مكانها دون نشر محتواها؛ لا يكفي hash شفرة المستودع.
- مطابقة شهادة APK المثبتة لبصمة شهادة المفتاح المحلي في phase-1-baseline.json؛ لا يكفي العثور على keystore في المستودع.
- تشغيل الفاحص في Termux ونجاح HTTP round-trip عبر aiohttp الحقيقي؛ لا تكفي إمكانية import أو تجربة Windows.
- تسجيل عينات منقحة من init وstep_update وresult لدورين متتابعين بنفس conversation_id، مع اختبار الاستئناف المحدد بعد إغلاق العملية.
- رفض أداة فعلية تحت قواعد الإذن القائمة مع توثيق CLI status وexit code؛ لا تُعدل القواعد للحصول على النتيجة.
- إلغاء دور جارٍ وإثبات إغلاق العملية المملوكة وأبنائها دون قتل أي Python آخر. لا يكفي إغلاق stdin.
- نتيجة Termux الصحيحة عبر PendingIntent؛ تمييز قبول الأمر عن جاهزية الخادم؛ ملء هذه الأدلة تجربة على الهاتف، لا من المساعدة.

إذا أخفق شرط أو بقي بلا دليل، فالمرحلة in_progress مع بيان العائق. لا تعني نتيجة الفاحص المحلي وحدها قبول المرحلة، حتى إذا نجحت عقود المساعدة.

## حفظ الأصل

phase-1-baseline.json سجل بصمات الملفات المتتبعة والشهادة العامة المستخرجة بقراءة ephemeral دون تصدير المفتاح الخاص. لا يحتوي نسخة بيانات مستخدم أو إثبات APK مثبتة. تبقى ملفات التطبيق والخادم والأصول وملفات توقيع البناء دون تعديل في هذه المرحلة.
