# خطة إعادة الهيكلة المعتمدة

تاريخ الاعتماد: 2026-10-04. الفرع: `codex/refactor-phase-1`.

## المقصد والحدود

إعادة بناء الداخل مع حفظ الهيئة والوظائف المثبتة والمحادثات والإعدادات وهوية الحزمة وشهادة الترقية. تبقى Java وPython وترتيب Android الحالي، والتخزين المحلي JSON/NDJSON. تُفصل المسؤوليات في ملفات متجاورة، ولا تُضاف قاعدة سحابية أو Docker أو إطار ثقيل. يُستبعد universal-software-agency.

أذن المستخدم صراحة بتنفيذ بقية المراحل على الفرع نفسه. يشمل النطاق إعادة بناء الإنتاج وفحصه محلياً؛ وتبقى إعدادات المستخدم وشهادة الترقية محفوظة. قبول الهاتف شرط اعتماد الإصدار، لا مانع بدء التنفيذ المحلي. تطابق CLI في Windows وTermux قرار مقرر من المستخدم؛ لا يحتاج سؤالاً آخر، لكنه لا يثبت دورة حياة الهاتف أو تثبيت aiohttp فيه.

## البناء المستهدف

- Python داخل Termux يملك الخادم والجلسات وعمليات agy. Activity مستهلك للحالة؛ AccessibilityService يملك أفعال الهاتف. لا خادمان متنافسان، ولا قارئان لأحداث العملية، ولا كاتبان للإعدادات.
- HTTP على aiohttp/asyncio وعقد `/api/v1`، وواجهة ومتصفح على loopback مع الاقتران والمصادقة وCSRF وفحص Host/Origin. لا CORS عام.
- جلسة stream-json مستمرة، ودور نشط واحد وانتظار result. الاستئناف بمعرف conversation_id الحقيقي؛ تغيير مجلد العمل أو النموذج أو الوكيل ينشئ جلسة جديدة. نتائج الأدوات منفصلة عن اكتمال الرد.
- الإلغاء ينهي مجموعة العملية المملوكة، ولا يغلق stdin وحده؛ لا SIGSTOP ولا موافقة وهمية ولا dangerously-skip-permissions. تبقى قيم الإذن كما وضعها المستخدم.
- أوامر agy المحلية مرجع إدارة MCP والنماذج والوكلاء. أوامر MCP الكاتب الوحيد، مع تسلسل التعديل وحفظ بقية القيم والتحقق من أثر CLI في ملف تجريبي معزول لاحقاً. لا اتصال مباشر بخدمات Google باستخدام رموز مستخرجة.
- الحفظ ذري برقم مراجعة ونسخة سابقة، مع المفاتيح المجهولة وUTF-8/BOM. حدود ملفات API بعد حل الروابط؛ لا تُخلط بصلاحيات الوكيل.
- مصدر واحد للويب وPython. Alpine CSP وTailwind CSS محليان؛ توليد CSS عند إصدار الحزمة فقط. لا إعادة بناء المحادثة عند كل fragment، ولا تغيير التركيز. Markdown بمحلل وتنقية واحدين.
- السجل الأصلي لدى Python، ونسخ JSON للقراءة في IndexedDB لكل مستهلك؛ Service Worker للأصول الثابتة فقط. الصفحة المحلية لإصلاح الاتصال، ولا إعادة تلقائية للأفعال عند عودته.
- أفعال الهاتف JSON معلومة ومعرف action_id وبصمة طلب وسجل قبل التنفيذ. نتيجة مجهولة لا تعاد آلياً. لا Lua مولد ولا shell عام؛ الصوت مهمة واحدة قابلة للإلغاء.
- إصدار ثابت ببيان موقع وبصمات، وبيانات خارج ملفات الإصدار. الترحيل إضافي والرجوع يحفظ البيانات الجديدة. شهادة release باقية، وdebug منفصل لاحقاً. APK الاسترداد يحتاج versionCode أعلى.

## المراحل ودليل القبول

| المرحلة | العمل | دليل الانتقال |
|---|---|---|
| 1 | خريطة الوظائف، العقود، بصمات الأصل والشهادة، فاحص قابل للتكرار | العقود محفوظة، وبيانات الهاتف مؤمنة، ونجاح aiohttp والدور المتتابع والإذن والإلغاء في Termux |
| 2 | توحيد المصدر وعزل ملكية العمليات | تشغيل من Android واقتران ودوران وبث وإلغاء وإعادة فتح Activity |
| 3 | HTTP والمصادقة والحفظ | العزل والتعارض والاستعادة بلا نجاح زائف |
| 4 | الواجهة وCLI وMCP | الوظائف المثبتة في المتصفح وWebView أو بيان تعذر صريح |
| 5 | Android والتحكم والصوت | نتائج فعلية وموارد مغلقة واختبار قارئات الشاشة |
| 6 | التثبيت والترقية والرجوع | نسخ مختلطة وترقية تحفظ البيانات ورجوع مجرب |
| 7 | إزالة القديم وتوثيق الإصدار | اجتياز القبول الكامل وعدم فقد الشهادة أو البيانات |

## تنفيذ المرحلة الأولى

1. تثبيت الفرع وبصمات الملفات المتتبعة العامة والإنتاجية والشهادة العامة؛ لا تصدير للمفتاح الخاص ولا مزامنة للنسخ.
2. ربط REQ-001..018 بمصادره وبحالته الموثقة، وفصل الادعاء التاريخي عن الإثبات الفعلي. لا فتح لشفرة الإنتاج لمجرد توثيقها.
3. إعداد `scripts/phase1_preflight.py` لعقود المساعدة وتجربة HTTP فعلية مؤقتة وبيان نواقص Termux. لا تثبيت أو تحديث أو تسجيل دخول أو تعديل MCP ضمن الفاحص.
4. إعداد فحوص مركزة في `scripts/run_tests.py`؛ التحقق من المهل والمدخل المخالف وحالات عدم التوافر، وأن المساعدة لا تتحول إلى إثبات للدور الحي.
5. حفظ نتيجة الفحص وقواعد قبول الهاتف. إن غاب الهاتف يبقى القبول الهاتفي unverified؛ ويجيز إذن المستخدم الأخير مواصلة التنفيذ المحلي.
6. تحديث سجل العمل والحالة والتغيير ومرجع الفاحص، ثم مراجعة مستقلة والتأكد من بقاء جميع بصمات الإنتاج كما هي.

## معايير الصيانة والفحص

كل جزء يملك بياناته وواجهة محدودة؛ لا متغيرات مشتركة بين الأجزاء ولا اعتماد على تفاصيلها الداخلية. يمكن إضافة فعل للهاتف أو مسار API دون تعديل ما لا يخصه، واختبار CLI والحفظ منفصلين عن Android والويب.

الفحوص المتتابعة: التزامن وتكرار الطلب وNDJSON والخروج المبكر ورفض الأدوات والإلغاء واستئناف SSE؛ المصادقة وCSRF والروابط؛ الحفظ والترحيل؛ نتائج الهاتف والمهل؛ النسخ والتوقيع والترقية؛ TalkBack وJieshuo والتركيز والملصقات والتباين. Python يمر black وflake8؛ ملفات التغيير تمر git diff --check. لا بناء APK مطلوب في مرحلة توثيق العقود والفاحص فقط.

القيم المستهدفة الجديدة عند غياب قيمة قائمة: دوران نشطان، وطلب/سطر أقصاه 1 MiB، واحتفاظ أحداث منتهية 24 ساعة ضمن 32 MiB. عند 50 MiB لا يبدأ عمل جديد دون تسوية السعة؛ لا حذف للمحادثات. هذه حدود مستقبلية، وليست إعداداً طبقته المرحلة الأولى.
