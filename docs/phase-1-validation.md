# فحص المرحلة الأولى

هذا الفاحص لجمع أدلة محدودة قابلة للتكرار؛ ليس خادم التطبيق، ولا يشهد بقبول الهاتف. يلزم Python وعقد agy المحلي. اعتماد aiohttp في requirements.txt هو الإصدار الذي اجتاز التجربة المحلية، وليس ادعاء تثبيت في Termux.

## التشغيل

من جذر المشروع، شغّل:

```text
python scripts/phase1_preflight.py --output docs/phase-1-local-evidence.json --require-termux --strict --timeout 5
```

في Windows PowerShell اضبط PYTHONIOENCODING إلى utf-8 في الجلسة قبل أمر Python إذا لم يكن مضبوطاً. على الهاتف يلزم نقل الفاحص واعتماده إلى Termux وتشغيل الأمر من جذر النسخة؛ لا ينفذ الفاحص تثبيتاً أو تحديثاً تلقائياً.

## مرجع الخيارات

| الخيار | الحكم |
|---|---|
| --help | يعرض الاستخدام دون فحص تشغيل |
| --output | مسار JSON مختار؛ يجب وجود المجلد الأب؛ يُستبدل التقرير بعد كل فحص مكتمل |
| --timeout | مهلة الفحص بالثواني؛ الافتراض 10، والمجال أكبر من صفر إلى 60 |
| --require-termux | يجعل إثبات بيئة Termux شرطاً لازماً |
| --strict | يعيد فشلاً إذا بقي دليل قبول لازم غير مثبت |

لا --output: يخرج التقرير JSON في stdout، وأخطاء الفحص في stderr. مع --output: الملف أصل التقرير، وحال الفحوص العادية في stdout؛ لا تُحفظ تشخيصات CLI الخام. القيم confirmed/unverified/failed تميز إثبات الفحص وتعذره وإخفاقه.

رمز الخروج 0 يثبت نجاح الفحوص المنفذة في النمط غير الصارم، ولا يعني قبول المرحلة. رمز 1 يعني فشلاً أو شرطاً غير متحقق في النمط الصارم؛ رمز 2 خطأ تشغيل/كتابة تقرير أو استعمال arguments مخالف. مهلة CLI تقاس لكل أمر؛ لا يرسل الفاحص طلباً إلى النموذج ولا يفتح تسجيل الدخول.

## ما يثبته وما لا يثبته

المساعدة المثبتة توثق وجود الأمر وخياراته المطلوبة فقط. الفاحص يقرأ stdout وstderr عند نجاح --help، ويحتفظ بالوسائط والخيارات المعلومة لا نص العملية. تجربة aiohttp تنشئ خادماً وعميل HTTP فعليين على 127.0.0.1 بمنفذ مؤقت، وتغلق الموارد بعد التبادل.

phone_stream_multiturn وphone_cancellation وphone_permissions وphone_data_backup وphone_apk_signature وphone_termux_result شواهد يدوية غير منفذة في الفاحص. الفاحص لا يقرأ سجل الأدلة اليدوية؛ لذلك يرفض --strict القبول في كل تشغيل لهذه النسخة. اعتماد أدلة الهاتف شأن سجل قبول مستقل بعد استيفاء الشروط، ولا يجعل إعادة تشغيل الفاحص ناجحة تلقائياً. قائمة blocking_checks تبين النواقص المعلومة في هذه الحدود.

لا يقرأ الفاحص بيانات المستخدم أو keystore، ولا يعدل MCP أو الإذن أو الإنتاج. خط الأساس وشهادة التوقيع العامة وفحص ADB أدلة مستقلة جمعها تنفيذ هذه المرحلة، وليست من أعمال السكربت.

## الفحوص البرمجية

تشغيل الاختبارات: python scripts/run_tests.py. هي فحوص stdlib صغيرة، تراجع صيغ المساعدة الحقيقية وقناة stderr والمهل وعدم تسريب التشخيص وكشف Termux والحفظ الذري وتجربة aiohttp. تعذر aiohttp يُعلن skip، ولا يُقبل فحص الهاتف بسببه.

التحقق الميكانيكي: black --check --line-length 79 على ملفي scripts/phase1_preflight.py وscripts/run_tests.py، ثم flake8 على الملفين، ثم git diff --check. تحتاج الاختبارات مجلداً مؤقتاً قابلاً للكتابة؛ في هذه البيئة يُستعمل .tmp بإعداد TEMP/TMP للجلسة فقط.

المرحلة التالية مشروطة [بأدلة الهاتف](phase-1-contracts.md)، وتُستأنف من [سجل العمل](../task.md). لا يُنفذ نقل الإنتاج من هذه الوثيقة.
