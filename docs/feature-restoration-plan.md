# خطة استرداد وظائف main

2026-10-07 — `feat: restore main feature parity`؛ اعتمد المستخدم الخطة وبدأ التنفيذ المحلي. ليست إذنًا بتسجيل دخول أو ترقية CLI أو اتصال خارجي أو فعل على الهاتف.

**Goal:** استرداد وظائف main الفعلية وفق [معيار التكافؤ](feature-parity-spec.md)، مع إزالة نجاح الأصل المفترض وطرقه غير المأمونة.

**Architecture:** تبقى الوحدات المتجاورة في server/، وAPI/v1 المقترن، ومصدر الويب الواحد وجسر Android المقيد. CLI مالك اعتماده؛ لا محرك مستقل ضمن هذه الخطة. تفصل adapters ذات المسؤولية الواحدة، وتستعمل JSON محليًا حيث يلزم الحفظ.

**Tech Stack:** Python/aiohttp، CLI agy المثبت، Alpine CSP والأصول المحلية، Android Java وTermux؛ الفحوص القائمة نفسها. لا خدمة ثقيلة ولا إطار فحص جديد ولا مسارات جهاز ثابتة.

**Spec:** [حصر الأصل](main-feature-baseline.md)، [العقود](feature-restoration-contracts.md)، [مصفوفة القبول](feature-parity-spec.md). تُقدّم الأدلة الخاصة بالنسخة والمنصة على الاستنتاج من وثائق المنتج العامة.

**Global Constraints:** حفظ عمل المستخدم؛ لا commit/push/نشر؛ لا كشف اعتماد؛ لا تجاوز أذون؛ لا إعادة مجهول؛ لا تعديل إنتاجي قبل اعتماد هذه الخطة. approval الخطة يجيز التنفيذ المحلي والفحوص المحلية اللازمة، ولا يجيز تلقائيًا أفعال الحساب أو الترقية أو الهاتف.

**Review Focus:** إثبات العقد قبل كتابة الواجهة، وعدم تحويل ميزات CLI/IDE العامة إلى وعد مخصوص بـTermux، وعدم إنشاء وظيفة لم يملكها الأصل خفية.

## صفر — تثبيت النطاق والعقود

الملفات: وثائق التكافؤ، server/cli_client.py وcli_catalog.py وapplication.py، ومسارات الأصل ذات الصلة؛ فحوص scripts/run_backend_tests.py. تستكمل مقابلة routes/actions الأصلية مع الفرع، بما فيها Home وRecents والاستعادة بعد boot والصوت والملفات والسجل. لا يكفي جدول الثمانية وحده لإعلان التكافؤ.

تُكتب قائمة عمليات CLI مسموحة وفروق Windows/Termux ومصادر الإعداد والاعتماد. تُثبت هيئة quota print بفحص قراءة منفصل مأذون، ودعم update flags من HELP، وجذور المهارات، وسلوك permissions وإتاحة أدوات schedule/manage_task. يمنع auto-update بالمتغير الرسمي `AGY_CLI_DISABLE_AUTO_UPDATE=true` بعد فحص توافقه؛ لا يُعوّل على متغير غير موثق.

تعزل فحوص العقد عن حساب المستخدم: fixtures لنتائج منقحة وعمليات مزيفة مملوكة، ثم تجربة حقيقية معلومة الأثر إذا لزمت. لا نموذج ينتج فعلًا أثناء فحص اكتشاف الأدوات. تنتهي المرحلة بجدول contract_verified أو probe_needed لكل عملية؛ إن تعذر عقد ما يُعرض نقصه وقرار بديل محدد، ولا يعلن أنه مسترد.

## أولًا — الحصص والترقية

الملفات: server/cli_client.py، application.py، runtime_status.py، server/web/panels.js؛ فحوص الخلفية والويب القائمة. يُفصل quota الحساب عن CPU/disk/RSS. الواجهة تعرض وقت الجلب وآخر نتيجة صحيحة مع علامة القدم؛ الإخفاق لا يولد قيمًا افتراضية. حد زمن وحجم ومخرجات منقحة، ومسلك قراءة مستقل عن session stream.

فحص RED: print فاشل أو غير معروف لا يعطي حصة؛ تحديث وهمي ناجح لا يكفي دون تحقق النسخة، والنقر المتكرر لا يشغل updater مرتين. تنفيذ GREEN: adapter ضيق للأمرين، وطلب ترقية صريح يراعي الأعمال الجارية؛ حالة ترقية منفصلة ومؤشر نسخة مثبت. لا تستعمل -y قبل إثبات قبوله. تجربة updater الحقيقية خارج الفحص المحلي وتحتاج إذنًا خاصًا.

## ثانيًا — سياسة الأذون والمهارات

الملفات: server/storage.py، cli_catalog.py، cli_client.py، application.py، panels.js؛ وحدة server/cli_settings.py متجاورة إن اقتضى فصل قراءة إعداد agy وكتابته. endpoint policy مستقل عن إعداد Companion، يبين المالك والأثر ووقت قراءته، ويحفظ unknown keys ذريًا مع قفل ورجوع. تقتصر البداية على allow/deny/ask الرسمية؛ لا تحويل آلي لـsafe_mode/autopilot/allow_* دون عقد.

فحص RED: deny يمنع أثر fixture المسموح بمراقبته، وask في headless لا يعلن نجاح الأداة، والكتابة المتعارضة تحفظ الأصل أو ترفض بوضوح. المهارة خارج الجذر أو symlink متجاوز أو مفقودة لا تعلن نجاحًا. تنفيذ GREEN: إدخال cwd في الجرد وحصر المسارات؛ إثبات آلية التعطيل الفردي قبل تبنيها. إن اختير نقل قابل للرجوع لمهارة مملوكة، يُثبت توقف اكتشافها واستعادتها، ولا تمس مهارات plugin أو ملفات المستخدم بلا قرار واضح. لا يعد تحرير policy بديلًا عن جواب إذن تفاعلي لم يثبت عقده.

## ثالثًا — دخول agy وMCP

الملفات: cli_client.py وapplication.py وpanels.js؛ server/auth_flow.py وحدة واحدة لآلة حال الدخول إن ثبت احتياجها، ووحدة MCP مستقلة فقط إن احتاج البروتوكول مسؤولية منفصلة. أول قبول عقد: عملية agy تفاعلية محدودة، لا terminal عامًا؛ تدعم المنصة فعلًا، ويفهم إلغاءها قبل توصيل الزر. يصحح نص `agy auth` غير المعلن؛ لا يخترع أمر logout. يدير CLI اعتماده، ولا تستخرج JWT أو تحذف token files لإجباره على الدخول.

فحص RED: ملف اعتماد موجود أو exit0 وحده لا يثبت الدخول؛ cancel/timeout لا يمس اعتمادًا سابقًا ولا يترك عملية. MCP HTTP200 أو HTML أو initialize ناقص لا يثبت البروتوكول، وفحص الاتصال لا يثبت استخدام CLI للاعتماد. تنفيذ GREEN: حالات pending/ready/failed/cancelled ومصدر إثبات محدد، وتنقيح الرابط والنص ورمز الإدخال؛ OAuth بمسلك رسمي مثبت، وفحص initialize/tools/list منفصل منضبط. إذا لم يثبت استخراج حال CLI الأصلية، يسجل انتظار دليل ولا يبدلها بنجاح مصطنع. الاختبار بحساب أو خادم خارجي يُعرض بفعل محدد قبل تنفيذه.

## رابعًا — المهام وأفعال Android التي أثبتها الحصر

الملفات: cli_client.py وsessions.py وapplication.py وpanels.js؛ android_client.py وDeviceArguments.java وAntigravityAccessibilityService.java وLocalAutomationServer.java وFloatingVoiceController.java وVoiceCapture.java للفجوات المثبتة. تُربط أحداث schedule/manage_task وsubagents بمعرّف حقيقي وإلغاء العمل المملوك؛ لا completed بمضي مدة ولا kill بتغيير JSON فقط.

فحص RED: انقطاع النتيجة أو restart لا يعيد تنفيذًا مجهولًا ولا يعلن اكتماله؛ إلغاء مهمة لا يقتل شاهدًا مستقلًا. إن لم يثبت عقد CLI للجدولة، يعرض قرار مستقل بين الاقتصار على مراقبة مهامه الفعلية وإنشاء مجدول Companion دائم؛ لا يُنفذ الأخير ضمنًا لأنه أوسع من الأصل. المجدول إن اعتمد لاحقًا يحتاج timezone وmissed-run policy ومعرّف وقوع محفوظًا وحالًا حقيقية.

يُفحص عقد توجيه الدور الجاري قبل إعادة /send؛ قبول الكتابة في stdin لا يثبت قبول CLI للرسالة. لا يعد صف انتظار للدور التالي مكافئًا، ويحتاج تغيير هذا المقصد قرارًا صريحًا إن غاب العقد. يستعاد عرض نسخ CLI والخادم وAPK بأسماء ومصادر منفصلة. تقابل حال ظهور التطبيق وخيارات التنبيه مع الويب وMainActivity؛ فحص RED يثبت عدم تكرار التنبيه بعد العودة وعدم كشف نص خاص، ثم يوصل مسلك visibility مقيد عند ثبوت الحاجة. لا إذن إشعارات تلقائيًا ولا تغيير خفي لخيار المستخدم.

أفعال الجهاز المكتوبة في main تدخل سجل الأفعال الحالي مع حفظ request_id وHMAC وحصر الوسائط وقبول النتيجة. تثبت unit tests العقد وحده؛ Home/Recents وما شابههما يحتاج قبول هاتف منفصل، مع اجتناب تشغيل تطبيق أو تغيير إذن أثناء فحص ساكن. يبقى الصوت المقبول سابقًا بمعياره الموثق، ولا تحول حال blocked إلى pass.

تستعاد Notifications وفتح التطبيق بحسب package محدد، مع مقابلة اختيار الاسم والاختصار الأصليين بمسلك محدد آمن؛ لا global_action برقم اعتباطي ولا code حر. إرسال startActivity ليس إثبات ظهور التطبيق. الوكيل الصوتي وTTS مقصد أصلي زائد على الإملاء: يصمم adapter حلقة محدودة برسائل وأفعال JSON محصورة ونتائج Android الفعلية، مع فصل التقاط الصوت وتنفيذ الأفعال وقول النتيجة. فحص RED: الكلام لا يطلق فعلًا غير معلوم؛ نتيجة click/launch فاشلة لا تُحكى نجاحًا؛ cancel يوقف الدور والأفعال اللاحقة؛ إعادة الطلب لا تعيد أثره. تنفيذ GREEN يحفظ خيارات الجلسة وسجل الدور وحدوده؛ لا تنفذ الشفرة التي يولدها الموديل. قبول الصوت والتحكم وTTS يحتاج الهاتف وقارئ الشاشة، ويظل منفصلًا عن فحوص fixtures.

## خامسًا — التدقيق والإقفال

بعد كل مرحلة تمر الشفرة clean-code-guard، والفحوص test-guard، والوثائق docs-guard؛ تشغيل فحوصها اللازمة قبل بدء التالية. تفحص Python بـblack/flake8 والفحوص القائمة؛ الويب بـNode/Chromium عند تغييره، وAndroid بوحداته وlint/build عند تغييره. لا يوسع الفحص إلى بناء لم تتغير مدخلاته بلا سبب.

قبل عرض GUI يفحص ترتيب Tab والأسماء والوسوم ورد التركيز ورسائل الخطأ وعدم حصر المعنى في اللون. قبل الحزم يولد SW ويطابق أصول APK وشهادة النسخة وعقد الخادم؛ الإصلاحات السابقة تبقى شروطًا لازمة. تصان البيانات ولا يرفع رقم النسخة أو يصدر Release لمجرد اكتمال الخطة.

يحدّث task.md وproject_state.md وCHANGELOG.md، وSKILL.md لكل واجهة أو عمل CLI تغير. تقرير التكافؤ يذكر كل صف وحال الدليل والباقي. قبول Termux والحساب وMCP والهاتف/OTA مراحل حقيقية منفصلة معلومة الأثر؛ نجاح الفحوص المحلية لا يغني عنها. تظل دعوى التكافؤ الكامل معلقة حتى إتمام جميع الوظائف الأصلية المطلوبة أو قرار صريح من المستخدم بشأن كل استثناء.

## ترتيب الاعتماد

يعتمد المستخدم النطاق والمراحل أولًا وفق شرط الخطة في AGENTS.md. التنفيذ المحلي يبدأ بالمرحلة صفر ثم الأولى والثانية، ولا ينتقل إلى adapter مجهول قبل إثباته. يُعرض أي قرار يوسع الأصل، أو فعل حساب/ترقية/هاتف، وحده عند الحاجة. يمكن توزيع البحث والفحص على وكلاء مستقلين، مع بقاء كتابة الملف الواحد تحت مالك واحد ومراجعة الحصيلة قبل المتابعة.

## قرار الجدولة وتوجيه الرسالة 2026-10-08

اختار المستخدم الخيار الأول صراحة: مجدول Companion محلي محفوظ، وتأجيل الرسالة إلى الدور التالي مع بيان ذلك. التنفيذ LocalTasks في server/local_tasks.py، JSON ذري تحت جذر الحفظ، وAPI /local-tasks مستقل. موعد واحد ISO8601 بمنطقة زمنية صريحة؛ missed_policy skip أو run_once معلنة. صف الرسائل FIFO لكل session؛ لا قطع للدور الجاري. يحفظ occurrence/request_id قبل الإرسال ويقابل runs عند restart؛ dispatch مجهول لا يعاد. النتيجة من Sessions لا من الساعة؛ الإلغاء الحقيقي للعمل المملوك. worker كل ثانية أثناء حياة السيرفر، ويتوقف قبل تنظيف Sessions. لا cron نظام أو تنفيذ حين يكون السيرفر مغلقًا؛ الموعد الفائت يخضع للخيار المحفوظ عند عودته. الويب يقدم حقولًا ذات أسماء وإلغاءً وعرض run الحقيقي. فحوص RED/GREEN للهويات والتعارض وFIFO والفوات وrestart والإلغاء وCSRF، ثم Python/Node وAPK وبصمة SW. لا هاتف أو متصفح.
