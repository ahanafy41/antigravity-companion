# قبول الهاتف بالسكربت

2026-10-04؛ الإصدار المثبت 1.3.2/8. طلب المستخدم تنفيذ أول أبواب القبول المتبقية كاملة بالسكربت.

## التشغيل

من جذر المستودع: `python scripts/run_phone_tests.py --phase all --speech-audio .tmp/phone-acceptance/speech.wav`.

يلزم ADB وهاتف مصرح، وCompanion وخادمه المقترن، وTermux واعتماد agy الجاري. `--help` مرجع الخيارات، و`--serial` يعين الهاتف عند تعدد الأجهزة. `--output` يعين مجلد التقرير، و`--resume` يقرأ التقدم السابق دون إعادة دور مجهول. لا يمسح الفاحص البيانات ولا يبدل الأذون أو الإعدادات أو خدمة قارئ الشاشة.

فاحص الحاسوب يشغل فاحص API في جلسة Termux مستقلة؛ يعتمد مسارات التطبيق من النظام ويحتفظ بمعرفات التقدم داخل تخزين Termux الخاص. ملف التقرير وحده منقح: أسماء الفحوص وحالات pass/fail/blocked وأسباب معلومة ومدة التنفيذ. XML والشجرة والرمز ومحتوى المحادثة لا تحفظ على الحاسوب.

## شروط الإثبات

- المحادثة: دور مكتمل ومعرف حقيقي، واستعادة علامة لا تتضمنها رسالة السؤال، وأحداث SSE قابلة للإعادة؛ إلغاء دور جارٍ وزوال العملية المملوكة وبقاء شاهد مستقل، ثم استئناف المحادثة نفسها.
- أفعال الهاتف: الضغط يفتح قائمة Companion، والتمرير يغير حدود محتوى الهدف نفسه، والرجوع يغلق القائمة ويبقي Companion ظاهرًا؛ قبول الفعل وحده لا يكفي.
- الصوت: إلغاء فعلي مع ثبات المسودة، وإملاء عبارة عربية معلومة عبر الميكروفون ووصول الكلمات إلى المسودة، وثبات سجل الأدوار كي لا تُرسل تلقائيًا.

النص الصوتي «هذه رسالة اختبار صوتي لا ترسلها» ولد محليًا بصوت Microsoft Hoda بواسطة [SpeechSynthesizer](https://learn.microsoft.com/en-us/uwp/api/windows.media.speechsynthesis.speechsynthesizer). file WAV محفوظ تحت .tmp؛ يحتاج وصول الصوت من مكبر الحاسوب إلى الميكروفون. لا يثبت إدخال نص عبر ADB الإملاء؛ عقد [RecognizerIntent](https://developer.android.com/reference/android/speech/RecognizerIntent#EXTRA_AUDIO_SOURCE) يبين اختلاف مصدر الصوت عن نص النتيجة.

## النتيجة الجارية

الدورة الفعلية على 1.3.2: chat_session وchat_initial وchat_recall وchat_cancel وchat_resume وdevice_menu_click وdevice_scroll نجحت. device_menu_back أخفق لأن Activity خرجت والقائمة مفتوحة. voice-before حفظ خط الأساس، ثم تعذر إثبات إنشاء جلسة Termux جديدة في voice-after؛ النتيجة الصوتية لم تحفظ في التقرير الأول ولا يجوز استنتاج نجاحها. أُصلح حفظ نتائج الصوت فور كل فحص، وتحري جلسة جديدة بالمعرفات بدل العدد المتغير، ولم تعد الدورة بعد ذلك.
